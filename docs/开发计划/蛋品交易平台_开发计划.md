## 1. 项目概述

面向鸡蛋产业链的 B2B 交易平台，包含 **养殖端、客户端、业务端、财务端** 四个业务端口和一组 **基础模块**，核心业务为"交割仓 + 平台垫资"模式下的蛋品交易，支持三种销售模式：

- 模式① 蛋库出库标准模式（客户付20%定金，平台垫80%，现场装车核验，扫码核销放行）
- 模式② 在途货物预付模式（远端客户，运满满叫车，GPS在途追踪，养殖户收齐全款才放行）
- 模式③ 渠道账期服务模式（如京东60天账期，风控尽调前置，尾款内扣平台分利）

### 1.1 估算前提

| 假设项 | 取值 |
|---|---|
| 团队配置 | 后端 2 人 + 前端 1 人 + 测试/实施 0.5 人（兼职） |
| 技术栈 | 按设计文档：FastAPI + Vue3，不中途换栈 |
| 第三方接口 | 电子签、电子发票、银企直联、运满满、GPS 均按"有成熟 SaaS/开放接口可对接"估算 |
| 范围 | 含管理后台；不含原生 App（四端均为 Web，移动端用 H5 响应式适配） |

> 若团队人数不同，第 3 章给出按人日换算的口径，可自行折算。

### 3.2 总工期

按 **后端 2 人、前端 1 人** 配置：

- 后端：194 ÷ 2 ≈ 97 工作日 ≈ **4.5 个月**
- 前端：110 ÷ 1 ≈ 110 工作日 ≈ **5 个月**（与后端并行，后期联调）

**含测试、联调、试运行，整体交付周期：约 5.5～6.5 个月。**

> 参考口径：
> - 若 1 人独立全栈开发：约 11～13 个月
> - 若 3 后端 + 2 前端：可压缩到 4 个月左右
> - 银企直联、运满满等外部接口的商务/审批周期不可控，建议项目启动**第一个月就发起对接申请**，否则可能成为关键路径

## 4. 里程碑计划（按 6 个月排期）

### 第 0 阶段：环境与脚手架（第 1–2 周）
- Docker Compose 开发环境（PostgreSQL 15 / Redis 7 / RabbitMQ / MinIO）
- 数据库完整建库脚本（按第三批文档的表设计 + 需求清单补字段）
- FastAPI 工程骨架（gateway + 各 service 分层模板、JWT、统一返回格式、全局异常）
- Vue3 工程骨架（Vite + Pinia + Router + Element Plus + Axios 封装 + 权限路由）
- Git 仓库与分支规范（main/develop/feature/*）、CI 流水线（lint + pytest）
- **同时启动**：电子签、发票、银企直联、运满满、实名认证的商务对接申请

### 第 1 阶段：地基模块（第 3–6 周）—— M1 + M2 + M13
- 用户注册/登录/JWT/RBAC 权限与数据隔离
- 企业建档、证照上传（MinIO）、实名认证、准入审批（F1.1/F1.2/F1.4）
- 自定义审批流引擎（节点配置 + 流转 + 留痕），后续所有审批复用
- 全局消息通知（站内信 + 短信）
- **里程碑 M1：四端可注册建档并完成准入审批**

### 第 2 阶段：建仓入库（第 7–9 周）—— M3 + M4
- 仓库登记、租赁审批（F2.1）
- 产蛋数据录入、交割仓审批建立、库存初始化（F2.3）
- IoT 视频监控接入确权、点位图上传（F2.2）
- **里程碑 M2：交割仓可建立，库存可初始化，监控在线**

### 第 3 阶段：交易核心（第 10–14 周）—— M5 + M6 + M7
- 现货货架（库存自动上架、指定/非指定养殖户筛选，F4.1）
- 建单销售/采购、20% 定金支付锁定（F3.1/F4.2）
- 三种销售模式状态机（F10.1/F10.2/F10.3）
- 出库单三方确认（水印照片/视频）、尾款支付（F5.1/F5.2）
- 核销二维码生成与扫码放行、库存实时扣减（F5.3）
- 订单跟进与异常处理（F4.3）
- **里程碑 M3：模式①全流程可跑通（定金→垫资→核验→尾款→核销放行）**

### 第 4 阶段：资金与合同发票（第 15–18 周）—— M8 + M9
- 80% 垫资付款审批 + 银企直联自动付款（F6.1/F9.7）
- 20% 尾款结算（含模式③分利内扣，F6.2）
- 入驻电子合同、销售合同、在线签署存证（F1.5/F3.2/F9.3）
- 电子发票开具/查验/归档（F6.3/F9.4）
- 四端账单中心（F6.4）
- **里程碑 M4：资金闭环，合同发票线上化**

### 第 5 阶段：风控、对账与物流（第 19–22 周）—— M10 + M11 + M12 + M14
- 3天周转平仓预警、5类退仓/自销申请（F7.1/F7.2）
- 超期强制平仓与 20% 折价处置（F7.3）、平仓退款审批与平仓台账（F7.4）
- 渠道风控尽调（F1.3）
- 对账中心（交割仓/自营，自动匹配 + 差异调账留痕，F8.1/F8.2）
- 数据看板与报表导出（F8.3）、归档与月度台账（F8.4）
- 运满满叫车 + GPS 轨迹（F9.8/F9.9）
- 满勤赠送机器人规则（F10.4）
- **里程碑 M5：全部功能完成（Feature Complete）**

### 第 6 阶段：测试与上线（第 23–26 周）
- 全流程联调测试（重点：资金流转、库存并发、扫码放行幂等）
- pytest 自动化测试补齐（核心资金流用例覆盖率 ≥80%）
- 性能压测（货架查询、库存扣减、对账批处理）
- 安全测试（越权访问、支付回调验签、SQL注入）
- UAT 验收、种子数据初始化、生产环境部署（K8s）
- 试运行 2 周 + 问题修复
- **里程碑 M6：正式上线**

## 5. 环境需求

| 软件 | 版本 | 用途 |

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 银企直联商务周期长（1–3个月） | 阻塞 M8 自动付款 | 第 1 周启动申请；先人工转账兜底 |
| 运满满/GPS 接口不确定 | 阻塞模式②在途追踪 | 先人工录入运单号 + 轨迹查询页兜底 |
| IoT 监控设备厂家多样 | M4 兼容工作量膨胀 | 优先支持 RTSP/GB28181 标准协议，非标设备逐个适配 |
| 三种销售模式资金规则复杂 | 资损风险 | 资金流全部走状态机 + 审批双确认；核心用例自动化测试全覆盖；对账中心每日校验 |
| 扫码放行是"唯一凭证" | 并发/重复核销资损 | 核销接口幂等 + 库存 Redis 分布式锁 + 数据库乐观锁 |
| 需求清单仍较粗（字段级未定义） | 开发中返工 | 每阶段开始前产出该模块的《页面字段与接口清单》并由业务确认 |
