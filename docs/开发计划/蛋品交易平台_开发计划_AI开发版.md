## 1. 为什么传统团队要 6 个月，AI 开发要多久

### 1.1 传统 6 个月的时间构成

| 时间消耗项 | 占比 | AI 开发时 |
|---|---|---|
| 样板代码（骨架、CRUD、分层、DTO） | ~30% | 基本消失（小时级） |
| 沟通/会议/需求转述/文档同步 | ~20% | 基本消失（你直接对我） |
| 前后端接口对齐、联调扯皮 | ~10% | 基本消失（同一人产出） |
| 真正的业务逻辑开发 | ~20% | 压缩约 50–70% |
| 需求确认、等待业务方决策 | ~10% | **无法压缩，取决于你** |
| 第三方接口商务与联调 | ~10% | **无法压缩，外部流程** |

### 1.2 结论

- **总工期：约 7–9 周**（从动工到上线试运行）
- 其中我实际开发约 **4–5 周工作量**，其余是：你的需求确认、分阶段审查验收、第三方沙箱联调
- **第 3 周末即可看到第一个可演示的完整业务闭环**（建档→建仓→上架→下单→核销放行，资金走模拟通道）

## 2. 什么步骤最耗时（重点关注）

按耗时/风险排序：

1. **需求细化确认（贯穿全程）** — 需求清单只到功能点级，字段级规则（出库单有哪些字段、折价 20% 怎么算、账期利息怎么记、评级规则）必须你来定。每次确认都是一次往返，这是总工期最大的变量。**对策：每阶段开工前我给一份《字段与规则确认清单》，你一次性回复。**
2. **三种销售模式的资金状态机（M6/M8）** — 平台垫资 80%、尾款 20%、模式③分利内扣、退款、折价处置，每条资金路径都要状态机 + 审批 + 对账兜底。这是代码量最大、测试最重的部分，约占总开发量 30%。
3. **第三方接口（M8/M9/M12）** — 银企直联（1–3 个月商务周期，本文档按"先人工兜底、接口到位后切换"处理，不占关键路径）、电子签、电子发票、实名认证 OCR、运满满/GPS。沙箱联调每个约 1–3 天。
4. **库存并发与扫码核销（M7）** — "扫码是放行唯一凭证"，涉及幂等、分布式锁、防重复核销，需要专门的压力与并发测试。
5. **你的审查轮次** — 每个里程碑你审查 → 我修 → 你复验，按经验每轮 0.5–2 天。6 个里程碑约 1–2 周累计。

## 4. 分阶段计划（共 7–9 周）

### 第 0 阶段：环境与骨架（第 1 周，约 2–3 个工作日）

我交付：
- Docker Compose 开发环境（PostgreSQL 15 / Redis 7 / RabbitMQ / MinIO），`docker compose up` 一键启动
- **完整建库 SQL + Alembic 迁移**（按需求清单补全字段：企业/证照、交割仓、库存流水、订单、三种模式资金流水、出库单、核销凭证、平仓台账、对账单、审批流定义/实例等，约 30–40 张表）
- FastAPI 骨架（gateway + 分层模板 + JWT + 统一返回 + 全局异常 + 日志）
- Vue3 骨架（Vite + TS + Pinia + Router + Element Plus + Axios 封装 + 四端布局框架 + 权限路由）
- Git 初始化、README、CI（lint + pytest）

你审查：表结构是否符合业务、跑通一键启动。
**里程碑 M0：环境可跑，骨架可启动。**

### 第 1 阶段：地基（第 1–2 周，约 4–5 个工作日）

- 用户注册/登录/JWT/RBAC + 四端数据隔离（F9.1）
- 养殖端/客户端建档注册、证照上传 MinIO、实名认证（先接 OCR 沙箱，可 mock）（F1.1/F1.2）
- **自定义审批流引擎**：节点可视化配置、流转/驳回/留痕（F9.2）——全平台 60% 功能依赖它，最先做
- 准入审批（F1.4）、全局消息通知（站内信 + 短信接口预留）（F9.5）

**里程碑 M1：四端可注册建档，准入审批线上流转。**

### 第 2 阶段：建仓入库（第 2–3 周，约 3–4 个工作日）

- 仓库登记 + 租赁审批（F2.1）
- 产蛋数据录入、交割仓审批建立、库存初始化与流水（F2.3）
- IoT 监控接入确权、在线状态、点位图上传（F2.2）——优先 RTSP/GB28181 标准协议

**里程碑 M2：交割仓可建、库存可入、监控在线。**

### 第 3 阶段：交易核心（第 3–5 周，约 8–10 个工作日，**开发量最大**）

- 现货货架：库存自动上架、指定/非指定养殖户筛选（F4.1）
- 建单销售/采购、20% 定金支付锁定（F3.1/F4.2）
- **三种销售模式状态机**（F10.1/F10.2/F10.3）——资金走模拟支付通道，接口预留
- 出库单三方确认（水印照片/视频上传）（F5.1）、尾款支付（F5.2）
- **核销二维码 + 扫码放行 + 库存实时扣减**（幂等 + Redis 锁）（F5.3）
- 订单跟进、异常处理（补/退/换）（F4.3）

**里程碑 M3：模式①全流程可演示（定金→垫资→核验→尾款→扫码放行）。这是你最重要的中期验收点。**

### 第 4 阶段：资金与合同发票（第 5–6 周，约 5–6 个工作日）

- 80% 垫资审批付款、20% 尾款结算（含模式③分利内扣）（F6.1/F6.2）
- 银企直联：先人工转账 + 回单上传兜底，接口模块按适配器模式预留（F9.7）
- 电子合同：入驻合同 + 销售合同，在线签署存证（对接 e签宝/法大大沙箱）（F1.5/F3.2/F9.3）
- 电子发票开具/查验/归档（F6.3/F9.4）
- 四端账单中心（F6.4）

**里程碑 M4：资金闭环（模拟通道），合同发票线上化。**

### 第 5 阶段：风控、对账、看板、物流（第 6–7 周，约 5–6 个工作日）

- 3 天周转平仓预警、5 类退仓/自销申请（F7.1/F7.2）
- 超期强制平仓 + 20% 折价处置、平仓退款审批与平仓台账（F7.3/F7.4）
- 渠道风控尽调（F1.3）
- 对账中心：单据自动归集匹配、差异调账留痕、自营对账（F8.1/F8.2）
- 数据看板（ECharts）+ Excel 导出 + 月度台账归档（F8.3/F8.4）
- 运满满叫车 + GPS 轨迹（先运单号人工录入兜底）（F9.8/F9.9）
- 满勤赠送机器人规则（F10.4）

**里程碑 M5：Feature Complete，全部功能可用。**

### 第 6 阶段：测试加固与上线（第 7–9 周）

- 核心资金流 pytest 全覆盖（垫资/尾款/分利/退款/折价，每条路径正反用例）
- 并发测试：库存扣减、扫码核销幂等（压测脚本）
- 安全自查：越权、支付回调验签、SQL 注入、文件上传
- 你的全流程 UAT（按三种模式各走 3–5 单）
- 生产部署（K8s manifests + 云资源配置清单）、种子数据、监控告警
- 试运行陪跑 + 修问题

**里程碑 M6：上线。**

## 6. 环境需求（AI 开发版）

### 6.1 你的本机（也是开发机）
- macOS，已装：Docker Desktop、Python 3.12、Node 20、Git（如缺我会帮你装）
- 16GB 内存以上

### 6.2 需要你申请/提供的账号（按优先级，越早越好）

| 优先级 | 项目 | 用途 | 没有怎么办 |
|---|---|---|---|
| 🔴 第 1 周 | 云服务器（测试环境，4核8G） | 部署演示环境供你随时审查 | 前 2 周可用本机 |
| 🔴 第 1 周 | 域名 + 备案（如需） | 正式上线 | 测试期用 IP |
| 🟡 第 2 周 | 阿里云/腾讯云账号（实名 OCR + 短信 + OSS） | F1.1 认证、F9.5 通知、文件存储 | 先 mock，本地 MinIO |
| 🟡 第 3 周 | e签宝或法大大企业账号（沙箱） | F9.3 电子合同 | 先 PDF 生成 + 线下签兜底 |
| 🟡 第 4 周 | 支付商户号（微信/支付宝） | 定金/尾款真实收款 | 全程可先用模拟支付通道 |
| 🟠 第 5 周 | 发票服务商（百望/航信） | F9.4 电子发票 | 先登记 + 上传扫描件兜底 |
| 🟠 第 6 周 | 银企直联（开户行）、运满满端口 | F9.7/F9.9 | **人工转账/录单兜底，不阻塞上线** |

> 设计原则：**所有第三方依赖都走适配器接口 + 人工兜底实现**。任何一家接口没到位，平台都能完整跑业务，只是某些环节从"自动"降级为"人工确认"。

### 6.3 生产环境（上线时）

- 应用：2×4核8G（K8s 双副本）
- 数据：云 RDS PostgreSQL 15 + 云 Redis + OSS 对象存储 + 云消息队列
- 运维：域名 + HTTPS、Prometheus + Grafana 监控、日志采集
- 预估云成本：约 1500–3000 元/月（按量，初期可更低配）

## 7. 风险与对策（AI 开发版）

| 风险 | 对策 |
|---|---|
| 需求字段级确认慢，成为瓶颈 | 每阶段清单化确认；你超过 3 天未确认的部分我按合理默认实现并标注，后续可改 |
| 三种模式资金规则复杂，资损风险 | 全部资金流转走状态机 + 审批双确认；pytest 正反用例全覆盖；上线后对账中心每日自动校验 |
| 扫码核销并发资损 | 接口幂等 + Redis 分布式锁 + 数据库乐观锁 + 专项压测 |
| 我产出量大，你审查不过来 | 里程碑制交付，每次给你"审查操作指引"（点哪里/输入什么/预期结果），每次验收控制在 1 小时内 |
| 第三方接口商务周期不可控 | 适配器 + 兜底模式，接口到位后热切换，不影响主工期 |
| 业务规则中途变更 | 状态机与审批流均配置化设计，改规则多数不用改代码 |
